# 1️⃣1️⃣ 평가 — 학습된 AI로 팔로워암 혼자 움직이기

## 🎯 이 단계의 목표
- 학습된 모델을 불러와 **리더암 없이** 팔로워암이 과제를 수행하게 한다.
- 성공률을 기록하고, 실패 원인을 데이터 관점에서 분석한다.

## 🤔 지금 무슨 일이 일어나나?
7단계 원격조작에서는 **리더암(사람)** 이 팔로워에게 각도를 알려 줬다.
이제 그 자리에 **AI 모델**이 들어간다. 1초에 30번씩 카메라 2장과 팔 자세를 AI에게 보여 주면, AI가 "다음 각도"를 계산해서 팔로워에게 보낸다.
학습에 쓰지 않은 **새로운 상황**에서도 잘 해내는지 확인하는 것이 평가(Evaluation)이다.

---

## 1. 실행 전 안전 확인 (꼭!)
- [ ] 팔로워 주변을 비우고, **손을 팔 근처에 두지 않는다.** AI는 예상 밖의 동작을 할 수 있다.
- [ ] 카메라 위치·조명이 **녹화할 때와 같다.**
- [ ] 큐브를 녹화 때 썼던 위치 중 하나에 놓는다.
- [ ] 비상시 Ctrl + C를 누를 준비를 한다. 더 급하면 **팔로워 전원 어댑터를 뽑는다.**

---

## 2. 실행

### 방법 A로 학습했다면 (내 PC의 모델)

`C:\robot\my_settings.bat` 실행 후:

```bat
lerobot-rollout ^
    --strategy.type=base ^
    --policy.path=outputs/train/act_so101_pick/checkpoints/last/pretrained_model ^
    --robot.type=so101_follower ^
    --robot.port=%FOLLOWER_PORT% ^
    --robot.id=%FOLLOWER_ID% ^
    --robot.cameras="%CAMERAS%" ^
    --task="Put the cube in the box" ^
    --duration=60
```

### 방법 B로 학습했다면 (Hugging Face의 모델)
`--policy.path` 한 줄만 바꾼다.
```bat
    --policy.path=%HF_USER%/act_so101_pick ^
```

📖 **이 명령은?** 학습된 정책(AI)을 로봇에 올려 실제로 실행(rollout)한다.

| 옵션 | 뜻 |
|---|---|
| `--strategy.type=base` | 가장 기본 모드. AI가 움직이기만 하고 **녹화는 하지 않는다** |
| `--policy.path=...` | 사용할 AI 모델 위치 (내 PC 폴더 또는 Hugging Face 이름) |
| `--robot.~` | 팔로워암 정보. **이름(id)이 같아야** 캘리브레이션을 그대로 쓴다 |
| `--robot.cameras="%CAMERAS%"` | **녹화 때와 똑같은 카메라 이름(front, side)·해상도**여야 한다 |
| `--task="..."` | 과제 설명 문장 |
| `--duration=60` | 60초 동안 실행 후 자동 종료 (0이면 무한 실행) |

- `last` 폴더가 없으면 `checkpoints/020000/pretrained_model` 처럼 **번호 폴더**를 직접 쓴다.
- **리더암 옵션(`--teleop`)이 없다!** 이제 사람이 조종하지 않기 때문이다.
- 실행이 끝나면 팔로워암이 **시작할 때 자세로 천천히 돌아간다**(v0.6.1 기본 동작).

> 🚨 **카메라 이름이 다르면 AI가 망가진 값을 낸다.** 녹화 때 `front`, `side` 였다면 평가 때도 반드시 `front`, `side` 여야 한다. Juxi 위키 FAQ의 `mean is infinity` 오류가 바로 이 경우다.

## 3. 성공률 기록하기

같은 조건으로 10번 실행하고 표에 기록해 보자.

| 큐브 위치 | 시도 | 성공 | 실패 모습 (예: 못 집음, 떨어뜨림, 엉뚱한 곳) |
|---|---|---|---|
| 위치 1 (녹화했던 곳) | 2 | | |
| 위치 2 (녹화했던 곳) | 2 | | |
| 위치 3 (녹화했던 곳) | 2 | | |
| 녹화 위치들 사이 | 2 | | |
| 녹화 안 한 새 위치 | 2 | | |
| **합계** | **10** | | **성공률 = 성공 ÷ 10 × 100 = ___%** |

### 🤔 결과 해석 — 왜 실패했을까?
| 관찰 | 가능한 원인 | 다음 실험 |
|---|---|---|
| 녹화한 위치에선 성공, 새 위치에선 실패 | AI는 **본 적 있는 상황**만 잘한다 (일반화 부족) | 위치를 더 다양하게 녹화 |
| 집으러 가다 멈칫멈칫 | 시범 동작이 매번 달라 AI가 헷갈림 | 일관된 동작으로 다시 녹화 |
| 아예 엉뚱하게 움직임 | 카메라가 움직였거나 조명이 바뀜, 학습 부족 | 카메라 고정 확인, 스텝 늘려 재학습 |
| 집는 것까지는 되는데 놓치기 | 그리퍼 쥐는 순간 데이터가 부족 | 손목(side) 카메라 각도 조정 |

> 💡 **"상관"과 "인과"를 구분하자.** "스텝을 늘렸더니 성공률이 올랐다"는 관찰만으로 스텝이 원인이라고 단정할 수 없다. 그사이 조명이 바뀌었을 수도 있다. 한 번에 **하나의 조건만 바꿔** 비교해야 원인을 알 수 있다.

## 4. (심화) 평가하면서 녹화하기
평가 장면도 데이터로 남기고 싶다면 `--strategy.type=episodic` 을 쓴다. 이때는 데이터셋 이름이 필요하며, 관례적으로 `eval_` 로 시작한다.

```bat
lerobot-rollout ^
    --strategy.type=episodic ^
    --policy.path=outputs/train/act_so101_pick/checkpoints/last/pretrained_model ^
    --robot.type=so101_follower ^
    --robot.port=%FOLLOWER_PORT% ^
    --robot.id=%FOLLOWER_ID% ^
    --robot.cameras="%CAMERAS%" ^
    --dataset.repo_id=%HF_USER%/eval_so101_pick ^
    --dataset.no_stamp=true ^
    --dataset.single_task="Put the cube in the box" ^
    --dataset.num_episodes=10 ^
    --dataset.episode_time_s=30 ^
    --dataset.reset_time_s=15 ^
    --dataset.push_to_hub=false
```
📖 AI가 30초씩 10판을 수행하고, 판 사이 15초 동안 사람이 큐브를 다시 놓는다. 각 판의 영상이 저장되므로 나중에 실패 장면을 돌려 보며 분석할 수 있다.

- **데이터 늘리기**: 위치·물체를 늘려 100개 이상 녹화하고 재학습해 성공률 변화를 비교한다.
