## 2장. 첫 구동 & 스마트폰 앱 (02 폴더)

1. 야붐 제공 TF카드(전용 이미지 내장)를 나노 뒷면 슬롯에 삽입 → 전원 ON
2. 부저 3번 + LED 점등 확인 → **OLED에 표시된 IP 주소 기록**
3. 앱 설치: Play스토어/앱스토어에서 **"MakerControl"** 검색
4. 폰을 로봇 핫스팟(`jetbot-mini`/`12345678`)이나 같은 와이파이에 연결 → 앱에서 [FPV remote control] → 와이파이 아이콘 → OLED의 IP 입력 → Connect (포트 6000/6001은 그대로)
5. 앱으로 조종! 앞으로 안 가면 `/home/jetson/yahboom-jetbotmini/config.txt`의 속도값(0~255) 조정

## 3장. 개발 환경 (03 폴더) — 전용 이미지면 대부분 스킵

**3.1 PC 접속 도구** (알아두면 편리):
- **WinSCP** — 윈도우↔젯봇 파일 드래그 전송 | **Putty/Xshell** — SSH 터미널 | **VNC Viewer** — 원격 데스크톱
- **jtop** — `sudo jtop` 으로 CPU/GPU/온도/전원모드 모니터링 (DLI 과정에서 쓰던 것과 동일)

**3.2~3.4 (⚪ 전용 이미지 사용 시 스킵)** — NVIDIA 순정 이미지에서 젯봇 환경을 밑바닥부터 만드는 법 (pip → TensorFlow → PyTorch → JupyterLab → 젯봇 펌웨어 → 서비스 등록). PDF에 "factory image면 건너뛰라"고 명시됨.

**3.3에서 유용한 것 — 와이파이 연결 명령** (headless로 접속했을 때):

```bash
nmcli dev wifi                                        # 와이파이 목록 보기
sudo nmcli dev wifi connect 와이파이이름 password 비밀번호  # 연결
ifconfig                                              # 새 IP 확인
```

**전원 모드** — MAXN(4코어 고성능, 기본) vs 5W(2코어 절전):

```bash
sudo nvpmodel -q     # 현재 모드 확인
sudo nvpmodel -m0    # MAXN (AI 훈련 시 권장)
sudo nvpmodel -m1    # 5W
```

## 4장. AI 기초 (04 폴더) — DLI 수료자는 4.1만!

- **4.1 JupyterLab** — 크롬에서 `IP:8888` 접속(비번 yahboom). 셀 실행 `Ctrl+Enter`, 실행+다음 셀 `Shift+Enter`. **실습 하나 끝날 때마다 Kernel → Shut Down All Kernels** (카메라·메모리 해제!)
- 4.2 OpenCV — `imread/imwrite`, `VideoCapture`, 도형 그리기, `resize`, **HSV 색공간**(색인식의 기초: BGR→HSV 변환 후 색 범위로 마스크)
- 4.3 CNN — 합성곱 신경망 개념 (DLI에서 배운 내용)
- 4.4 TensorFlow / 4.5 PyTorch — 프레임워크 소개 + **ResNet-18 전이학습** 개념 (DLI와 동일)
- **4.5.3 가위바위보 실습** 🎮 (해볼 만한 것!) — `Notebooks/English/2.Simple_gesture_recognition.../`
  - `Collect_data.ipynb` (데이터 수집) → `Training_model.ipynb` (훈련) → `Man_machine_guessing.ipynb` (사람 vs 컴퓨터 대결)
  - ⚠️ **2GB 모델은 훈련 중 멈출 수 있음** — PDF 자체가 "미리 훈련된 모델 사용 권장"이라고 안내
- 4.6 CUDA/cuDNN/TensorRT — NVIDIA GPU 가속 도구 소개 (`device = torch.device('cuda')`가 왜 필요한지)

## 5장. 하드웨어 제어 (05 폴더) — 노트북 경로: `Notebooks/English/3~7`

| 절 | 내용 | 핵심 |
|---|---|---|
| 5.1 GPIO | 보드 LED 켜기, 버튼 읽기 | `RPi.GPIO`/`Jetson.GPIO` 사용. LED=BCM 24·23(Low에 켜짐), 버튼=BCM 8 |
| 5.2 I2C | 버스에 붙은 장치 확인 | `i2cdetect -r -y 1` → OLED(0x3C), 코프로세서(0x1B) 보임 |
| 5.3 코프로세서 | **부저·모터 제어** | 나노는 PWM이 없어 STM8 코프로세서가 대신 생성. `bus.write_byte_data(0x1B, 0x06, 1)` = 부저 ON. 모터는 `from jetbotmini import Robot` → `robot.left_motor.value = 0.8` |
| 5.4 OLED | 화면에 IP/메모리 표시 | SSD1306 드라이버. 실습 전 `sudo systemctl stop jetbotmini_stats` (기본 표시 프로세스 정지) |
| 5.5 배터리 | 전압 코드로 읽기 | 12V↑ High / 11.1V↑ Medium / 10.05V↑ Low / 9.9V↓ Empty. **배터리 부족 시 파란 LED가 빠르게 깜빡임** |
| 5.6 서보 | 카메라 각도 조절 | `bus.write_i2c_block_data(0x1B, 3, [서보번호(1~2), 각도(0~180)])` ※서보는 별매(SG90) |

## 7장. ROS 기초 (07 폴더) — 선택 심화

- **ROS** = 로봇용 오픈소스 운영체제(미들웨어). 노드(프로세스)들이 **토픽**(일방 구독/발행), **서비스**(요청/응답), **액션**(피드백 있는 작업)으로 통신
- 젯봇미니의 ROS 버전: **Melodic** (Ubuntu 18.04용)
- 필수 명령어 감잡기:

```bash
roscore                                   # 마스터(노드 관리자) 시작 — 항상 먼저!
rosrun turtlesim turtlesim_node           # 거북이 시뮬레이터 (연습용)
rosrun turtlesim turtle_teleop_key        # 방향키로 거북이 조종
rosnode list / rostopic list / rosservice list   # 실행 중인 것들 보기
rostopic echo /토픽이름                    # 토픽 내용 실시간 보기
rqt_graph                                 # 노드 연결 그림으로 보기
```

- **워크스페이스** : `~/catkin_ws/src`에 소스 → `catkin_make` 컴파일 → `source devel/setup.bash`
- **launch 파일** : 노드 여러 개를 한 번에 시작 — `roslaunch 패키지명 파일명.launch`
- 7.4 멀티머신: PC(가상머신)와 젯봇이 같은 와이파이에서 역할 분담. `~/.bashrc`에 `ROS_MASTER_URI` 설정

## 9장. ROS 로봇 제어 (09 폴더) — 선택 심화

**9.1 기본 통신** — 젯봇 하부 드라이버 노드가 제공하는 서비스들:

```bash
roscore
rosrun jetbot_ros jetbotmini_driver.py
# 다른 터미널에서:
rosservice call /Buzzer "buzzer: 1"                       # 부저 ON
rosservice call /Motor "rightspeed: 0.4
leftspeed: 0.4"                                           # 40% 속도 전진
rosservice call /Servo "angle: 90
servoid: 1"                                               # 서보1을 90도로
# /LEDBLUE, /LEDGREE 도 동일 (배터리 전압은 /voltage 토픽으로 발행)
```

⚠️ 서비스 콜은 복붙하지 말고 **직접 타이핑 + Tab키 자동완성** (형식 깨짐 방지)

**9.2 키보드 조종** — `roslaunch jetbot_ros jetbotmini_keyboard.launch` → `w/a/s/d` 이동, `u/j` 등으로 속도 조절 (초기 속도 0이니 먼저 올리기!), `q` 종료

**9.3 핸들 조종** — 이번엔 핸들 수신기를 **젯봇에** 연결 (6.2는 PC에 연결). `ls /dev/input`에 `js0` 확인 → `roslaunch jetbot_ros joy_bringup.launch`. 반응 없으면 핸들의 START 버튼!

## 11장. 배터리와 충전 (11 폴더) — 🟢 안전 필수

1. 충전할 땐 **배터리팩을 차에서 분리**해서 충전기를 DC 소켓에 연결
2. **충전하면서 사용 금지** (폭발 위험!)
3. 전압 11.1V쯤 되면 충전하기 — 만충 시 약 **12.6V**

## 15장. 하드웨어 참고 (개조할 때만)

- 핀맵: OLED=I2C1(0x3C), 코프로세서=I2C2(0x1B), LED=BCM24·23, 버튼=BCM8
- 코프로세서 레지스터: `0x01` 모터제어(방향+속도 0~255), `0x02` 전체정지, `0x03` 서보, `0x06` 부저, 전압 읽기 지원
- 앱 통신 프로토콜: `#robotforward` `#robotstop` `#speed1~3` `#buzzer` `#LED` 등 텍스트 명령

## 16장. FAQ — 문제 생겼을 때

| 증상 | 해결 |
|---|---|
| ROS master 시작 실패 | 멀티머신 설정 확인(호스트에서 roscore 실행했는지), `~/.bashrc`의 호스트 IP 확인, 네트워크 연결 확인 |
| 부팅 시 OLED가 안 나옴 | **와이파이 네트워크 카드를 꽂았는지 확인** 후 재부팅 |
| 카메라 코드 에러 | 카메라 연결 확인 → `ls /dev`에서 video0 확인 → JupyterLab에서 **[Kernel]→[Shut Down All Kernels]** 후 30초 대기 → 재실행. 계속 안 되면 재부팅 |
| 주피터에서 카메라 프리즈 | `nvgstcapture-1.0`으로 카메라 자체 확인 → `sudo systemctl stop jetbotmini_jupyter` → `start` 로 주피터 재시작 |
